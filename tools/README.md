# tools/

Developer tooling that is **not** part of the SvelteKit build. Unlike `scripts/`
(gitignored), everything here is committed so it can be shared and, later, wired
into CI.

## CFPS ⇆ autonomous-cfps sync

Keeps the CFPS designer in step with the `CFPSReagentList` pydantic model in the
private repo [`ginkgobioworks/autonomous-cfps`](https://github.com/ginkgobioworks/autonomous-cfps).
The model is the single source of truth for the reagent field names, the fixed
volumes / 25 nL grid / 20 µL total, the template rules, **and** the per-reagent
costs.

### Pieces

- **`extract_cfps_spec.py`** — imports the pydantic model (introspection, no
  source-parsing) and prints a canonical spec as JSON. Must run inside the
  autonomous-cfps environment.
- **`sync-cfps.mjs`** — orchestrator. Runs the extractor, writes the committed
  `src/lib/cfpsReagentSpec.generated.json` (the contract the app validates
  against — costs are stripped, it ships in the browser bundle), then pushes the per-reagent costs into the **live** PocketBase
  `cfps_reagent_groups` record so cost changes are near-instant with no rebuild.

- **Range checks** — the extractor also exports `rangeChecks` into the contract:
  the advisory per-composition checks from autonomous-cfps `validate_design`
  (watchlisted components and matched energy substrates within 0.5×–2× of the
  target's reference controls, plus "needs an ATP-regeneration substrate").
  Concentration factors, reference concentrations and watchlists are computed by
  calling the real Python, not re-derived. `src/lib/cfpsRangeChecks.js` ports
  the check logic with two policies: `'autonomous-cfps'` (exactly the Python,
  used by the parity test) and `'site'` (the default the designer and submit
  endpoints enforce — a deliberately much looser, site-only override: only a
  missing watchlisted component (zero) or one above `SITE_BAND.high` (10×) the
  highest of the target's reference controls flags, so alerts mean "will not
  work"). Out-of-range compositions are
  rejected unless the request sets `allow_out_of_range: true`.
- **`check-cfps-range-parity.mjs`** (`npm run check:cfps-range`) — replays
  `tools/fixtures/cfps-range-checks.fixtures.json` (recipes + the flags the real
  Python raised, regenerated by every sync) through the JS port and fails on
  any difference. Run it after each sync.

### Two update paths, on purpose

| What | Where it lives | How it updates | Why |
| --- | --- | --- | --- |
| Costs | PocketBase (`costPerMl`) | `--apply` writes live PB | instant, no redeploy |
| Contract (fields, constants, template rules) | committed `cfpsReagentSpec.generated.json` | commit + deploy | validation logic stays reviewable |

### Usage

```bash
# dry run: regenerate the JSON and print the PB cost diff (writes nothing to PB)
npm run sync:cfps

# also push the cost changes to live PocketBase (backs up the record first)
npm run sync:cfps:apply

# only regenerate the committed contract JSON, skip PocketBase entirely
node tools/sync-cfps.mjs --no-pb
```

Requirements: [`uv`](https://docs.astral.sh/uv/) on PATH, an autonomous-cfps
checkout (defaults to `../autonomous-cfps`, override with `AUTONOMOUS_CFPS_PATH`),
and `PB_EMAIL` / `PB_PASSWORD` (read from the environment or the repo `.env`).

After running, review the diff to `src/lib/cfpsReagentSpec.generated.json` and
commit it if the contract changed. PB backups are written to
`scripts/pb-backups/` (gitignored).

## CFPS clusters (`/cfps/clusters`)

The CFPS Arena cluster export predicts which coopetition designs will behave
alike. It names **every design with its author, sample_id, recipe and model
forecast**, so it is deliberately not in this repo (public) and not in
`static/` (world-readable). It lives as gzipped attachments on the
superuser-only `cfps_cluster_data` PocketBase collection and reaches the
browser through `/cfps/clusters-data/<file>`, which checks the Keycloak session
on every request. The page, its stylesheet and its loader script stay public —
only the data is gated.

### Analysing the data (start here)

You need a **CFPS agent token**: sign in at the site, switch the *Participate*
section to **Agent**, and click *Create agent token*. No PocketBase credentials
required.

```bash
npm install
npm run clusters:fetch -- --token=<your agent token>
```

That writes `data/cfps-clusters/` (gitignored), unpacking the gzip so both files
are plain JSON:

| File | What's in it |
| --- | --- |
| `clusters_designs.json` | one record per design: `author`, `sampleId`, `recipeNl`, `forecast.pBeat`, predicted `ln $/g` + `sd`, `round1Role`, `group` |
| `clusters.json` | the rendered view plus `tips`: a per-protein pairwise link matrix (549×549 for sfGFP), the 86 groups, and the design names behind them |

```js
const d = require('./data/cfps-clusters/clusters_designs.json');
d.proteins.sfGFP.designs.length;                 // 549
[...d.proteins.sfGFP.designs]                    // best predicted odds first
  .sort((a, b) => b.forecast.pBeat - a.forecast.pBeat)[0];
```

Maintainers with `PB_EMAIL` / `PB_PASSWORD` in `.env` can skip the token with
`npm run clusters:fetch -- --pb`. Add `--raw` to keep the files gzipped.

### Keeping it fresh

The clusters are *predictions from a trained model*, so they only change when
the exporter re-runs — not when someone submits. Re-export and publish in one
step:

```bash
npm run clusters:refresh -- --arena=../cfps-arena --apply
```

`--arena` is a CFPS Arena checkout (or set `CFPS_ARENA_DIR`); override the
command with `--cmd="…"`. Drop `--apply` for a dry run. If you already have an
export on disk, publish it directly:

```bash
npm run clusters:publish -- --dir=<export dir> --apply
```

To run it nightly, add a cron entry on a machine that has both the arena
checkout and the repo `.env`:

```cron
# 03:15 daily — re-export the clusters and publish them
15 3 * * * cd /path/to/ginkgo-artworks && /usr/local/bin/npm run clusters:refresh -- --arena=/path/to/cfps-arena --apply >> /tmp/cfps-clusters.log 2>&1
```

The page prints the export's build time, so staleness is always visible to
readers.

### CI later

The same `npm run sync:cfps` is CI-ready: a scheduled GitHub Action can check out
autonomous-cfps (read-only fine-grained PAT or GitHub App token), `uv sync` it,
run the script with `AUTONOMOUS_CFPS_PATH` set, apply costs to PB, and open a PR
when `cfpsReagentSpec.generated.json` changes.
